Scene Settings

3D scenes render with the built-in perspective camera — the same view you see in Preview. 2D objects keep drawing on top; HUD widgets still work.

Dims the whole scene. Lights punch soft holes in the darkness; objects with Cast shadow checked block the light. 0 = day, 100 = pitch black. Use the Set Darkness block to change it while the game runs.

How gently the camera chases the followed object. 0 snaps at once; 0.5 glides halfway there each frame; 0.9 is a slow cinematic drift. Use the Set Camera Smoothing block to change it while the game runs.

A rectangle around the center of the screen. While the followed object stays inside it the camera does not move. 0 x 0 turns the deadzone off.

A world rectangle the camera view stays inside, so the camera never shows past the edge of a room. Leave all four blank for no bounds (the scene edges apply). Use the Set / Clear Camera Bounds blocks to change them while the game runs.

A small live map in a corner, with a dot for every live object and a white rectangle for what the camera sees. The boss draws red, an object tagged player draws white, other tagged objects draw in their tag's color. Use the Show / Hide Minimap blocks to change it while the game runs.

1 fits the whole scene. Above 1 the map shows a window around the camera instead — 2 shows half the level, 4 shows a quarter — so a zoomed map follows the player. Use the Set Minimap Zoom block to change it while the game runs.

Frames the camera used by the 3D view, Preview, and exported games. Reset re-frames the whole scene.

Draws a soft dark ellipse under each 3D object on the ground plane below. Simple and cheap — not real shadow mapping.

The Y of the invisible ground plane shadows land on. Blank = the bottom of the world.

Assets

Images, audio files, and GIFs live here. Anything not used by a sprite or a scene background is marked unused, and safe to delete.

Input Actions

Name an action once, then bind keys, a gamepad button, and a touch zone to it. Blocks read the action — not the raw key — so the same logic works on keyboard, gamepad, and touchscreen, and players can remap keys in-game.

Audio Buses

Every sound plays through a bus. Music streams (long tracks stay out of memory, one at a time, loops by default); SFX and UI sounds are decoded once and kept in memory. Blocks can change bus volume and mute while the game runs too.

Localization

One string table for the whole game: name a key once (for example play_button), write it in every language, then read it with Set Text from Key or bind a text object to it. Set Language switches every bound label at once; a missing translation falls back to the default language.

Dialogues

Named conversations for the whole game: one line per row (who speaks, what they say), with choices that jump to another line. Start one with the Start Dialogue block, picking the two text objects the speaker and line appear in; advance it with a key or a Next button, and build choice buttons with Set Choice Text.

Items

Named items the player can carry: a key, a potion, a gem. Set the max stack (how many fit in the backpack at once; 1 makes a unique item) and a short description. Add them with the Add Item block, gate doors and shops with Has Item and Item Count, and read a count into a variable with Read Item Count.

Quests

Named objectives the player works through: collect 4 coins, defeat 3 enemies, reach the goal. Set the target (how much progress finishes the quest; 1 is a one-shot quest) and a short description. Add progress with the Add Quest Progress block, gate rewards and endings with Quest Complete and Quest Progress, and read progress into a variable with Read Quest Progress.

Achievements

Permanent trophies the player earns: beat every level, collect 100 coins, finish without dying. Unlike quests, which reset on a fresh run, an unlocked achievement stays unlocked across runs, scenes, and restarts. Unlock one with the Unlock Achievement block, gate rewards and endings with Achievement Unlocked and Achievement Count, and reset them all with Reset Achievements.

Cutscenes

Scripted scenes the game plays by itself: an intro, a level transition, an ending. Each cutscene is a list of steps that run in order — wait, show text in a label, glide an object somewhere, play a sound, switch scene. Play one with the Play Cutscene block, gate the HUD and player input on Cutscene Playing, and run what happens next on Cutscene Finished.

High Scores

The ranked leaderboard the game keeps for itself: the best scores, best first, kept across runs, scenes, and restarts like the achievements. Set how many entries the table holds and the default name for a score submitted without one, then submit scores with the Submit Score block, gate a "New best!" moment on Is High Score, and read ranks back into variables with Read High Score.

Variables

The scoped variables this game starts with: Global keeps a value for the whole run, Scene keeps one per scene (each visit starts from its starting value), Object keeps one per object name (the goblin's hp is not the hero's). Create one here and it exists from the first frame, no block needed; change it with the Set Scoped Variable block while the game runs. To watch the values change while you play, open Live variables in the Preview tab.

Functions

Reusable block chains: define a function once here (a name, up to eight parameters, and a body grid like any other scope), then call it from any row with the Call Function block. The parameters arrive as local variables, so two calls never see each other's values; Return hands a value back to the caller and stops the body. Edit body opens the function's own grid in the Logic tab.

Transitions

How scene changes look when they use the Transition to Scene block instead of an instant cut: the screen fades to black (or a black panel wipes across), the scene switches under full cover, then it fades back in on the new scene. Set the default effect and total time here; each block can override both for one switch, or leave them on Default. The plain Switch Scene block stays an instant cut.

Joystick

The on-screen stick for touchscreen play: a fixed base circle in a screen corner with a knob the player drags to steer. It writes its tilt into two game variables every frame (left is -1, right is 1, up is -1, down is 1; released it reads 0), and it can drive up to four named input actions from the Inputs tab, so a keyboard game becomes a phone game by naming four actions. Turn it on here to have it from the start, or flip it during play with the Enable / Disable Joystick blocks. A mouse drag grabs it too, for desktop playtesting.

Export your game

Pick a target. Every target is a complete, working package. Nothing is a black box: each card says exactly what the engine makes, what you do next, and what cannot be automated.

Single HTML file

One file with your whole game inside: engine, art, and sound. Double-click it to play, or put it on any website.

Plays offline · any browser · no install · big games make big files

  • Engine makes: one .html file with everything embedded. No internet needed to play it.
  • You do: click Download and keep the file.
  • Good to know: big games make big files, because the art and sound live inside the HTML.

Website ZIP (itch.io)

index.html plus an assets folder with your images and audio as separate files. This is the format itch.io expects.

itch.io ready · plays in any browser · no install · needs a web host

  • Engine makes: a ZIP with index.html and an assets/ folder. All paths are relative, so it works from any folder or host.
  • You do: on itch.io, make a project, upload the ZIP, set Kind of project to HTML, tick "This file will be played in the browser", set the viewport to your scene size, then publish.
  • Cannot be automated: uploading to your itch.io account and setting page options needs your login, so those steps are yours.

Installable app (PWA)

Everything in the Website ZIP, plus a web manifest, an offline service worker, and app icons. Players can install it to a home screen.

Installs to home screen · plays offline after first visit · needs HTTPS hosting

  • Engine makes: index.html, assets/, manifest.webmanifest, sw.js (offline cache), and 192px + 512px icons drawn from your game's name.
  • You do: unzip the folder, host it over HTTPS (itch.io, GitHub Pages, and Netlify Drop all work), open the URL once. The browser offers Install, and the game plays offline after the first visit.
  • Cannot be automated: publishing the folder needs your hosting account, and installing needs a tap from the player. The engine cannot do either for you.

Desktop app (Electron)

A complete Electron project that becomes real Windows, macOS, and Linux installers — not a web page.

Real installers · gamepad + full keyboard work · unsigned builds show an unknown-publisher warning

  • Engine makes: a full buildable project — package.json, a main.js window shell sized to your scene, a 512px icon drawn from your game's name, your game as game/index.html + assets/, and a README with the exact commands.
  • You do: unzip it, run (needs Node.js), then to play or to build the installers into dist/. Click a command to copy it.
  • Cannot be automated: building the binary runs on your computer — a browser cannot do it. The engine never signs or notarizes: unsigned builds play fine but show the usual unknown-publisher warning until you sign with your own certificate. For branded icons, convert build/icon.png to icon.ico / icon.icns; electron-builder picks those names up automatically.

Android app (Capacitor)

A complete Capacitor project that becomes a real Android APK — your game wrapped in a native shell.

Real APK · touch works through your input actions · debug build is free · Play Store needs your signing key

  • Engine makes: a full buildable project — package.json, capacitor.config.json, your game as www/index.html + assets/, a 1024px icon and splash drawn from your game's name, and a README with the exact commands.
  • You do: unzip it, run , then and , then for a debug APK you can install on your phone. Click a command to copy it.
  • Cannot be automated: the native project generates on your machine via npx cap add — a browser cannot do it. A Play Store release needs your own signing key.

iOS app (Capacitor)

A complete Capacitor project that becomes a real iOS app — the same native shell as the Android card, built for iPhone.

Real iOS app · requires macOS + Xcode to build · App Store needs an Apple Developer account

  • Engine makes: the same full buildable project as the Android card — package.json, capacitor.config.json, your game as www/index.html + assets/, a 1024px icon and splash, and a README with the exact commands.
  • You do: unzip it, run , then and on a Mac, then open ios/ in Xcode and build. Click a command to copy it.
  • Cannot be automated: an iOS binary REQUIRES macOS + Xcode: the engine produces the full iOS project, but Apple builds the binary. An App Store release needs your own Apple Developer account and signing.
