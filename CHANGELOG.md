# HydraScript — CHANGELOG

User-visible changes. Newest first.

## Unreleased

### Changed
- Object parenting: a game can now attach one object to another, so a sword rides in the hero's hand, a hat sits on a goblin, or a name tag floats above an NPC without re-aiming the child every frame. **Attach Object To Object** links a child to a parent at a fixed offset — leave the offsets blank to keep the spacing the objects already have — and the child follows the parent everywhere it goes; **Detach Object** unlinks it so it stays where it is; **Set Attachment Offset** slides an attached object to a new spacing without re-attaching; **Is Attached** is true while the object is attached to something, or to the named parent only. Attaching a child that already has a parent replaces the old link, and a link that would close a cycle warns and changes nothing. Links are position only and clear when the scene loads again, so attach again in a gameStart row. Old projects behave exactly as before: an object with no link simply has none.
- Minimap: a game can now show a small live map in a corner of the screen, so the player can see where things are in a big level at a glance. Turn it on per scene in Scene Settings under **Minimap** — pick the corner, the size from 80 to 400 pixels, and a zoom from 1 to 4, with a checkbox for the white rectangle that shows what the camera sees. At zoom 1 the map fits the whole scene; above 1 it shows a window around the camera that follows as the camera moves. Every live object draws as a dot: the boss draws red and large while a fight runs, an object tagged `player` draws white and large, other tagged objects draw in a steady color from their first tag so the same tag always reads the same color, and untagged objects draw gray. Hidden, destroyed, HUD, and light objects never draw. Five new blocks in a new **Minimap** category drive it while the game runs: **Show Minimap** and **Hide Minimap** flip it on and off, **Set Minimap Size** and **Set Minimap Zoom** change the run's size and zoom (clamped to the same limits), and **Minimap Visible** is true while the map shows, so a row can gate on it — give the player the map on pickup, then show the exit marker only once they have it. A bad size or zoom warns and changes nothing. One map per scene, and the map is positions only: no health bars or names on the dots. Old projects behave exactly as before: a scene with no minimap setting simply has none.
- Pick objects by tag: a tag can now pick one of its objects, not just count them. **Pick Nearest Tagged** is true while a live object carries the tag and points the rest of the chain at the closest one, so Pick Nearest Tagged goblin, then Damage Object, hurts only the nearest goblin; **Pick Farthest Tagged** takes the farthest, **Pick Random Tagged** takes any one of them. **Pick Tagged Object Into Variable** holds the pick in a variable — nearest, farthest, random, or first — so Read Object Property can read its position, health, or name back even when the tagged objects have different names. **For Each Tagged Object** runs the blocks to its right once for every live object carrying the tag, in live order, with an optional object variable holding the current one and an index counting 1, 2, 3, so the same chain can damage every goblin or move every coin. Matching ignores capitals, so Goblin and goblin are the same tag. A chained action only narrows onto the picked object when it names that object's name — when the tagged objects have different names, hold the pick in a variable first. A blank tag warns and holds on the action blocks and stays quiet on the pick conditions. Old projects behave exactly as before.
- Object tags: a game can now ask about a whole group of objects at once instead of one name at a time. A tag is a plain label on an object — goblin, coin, boss, collectible — set in the Inspector **Tags** section, where an object's tags show as chips with an add box. **Add Tag** sticks a label on a live object while the game runs, **Remove Tag** takes one off, and **Clear Tags** takes them all off; **Has Tag** is true while any live object with the name carries the tag, so a goblin can be elite and a coin can be golden; **Tagged Count** compares how many live objects carry the tag, so the classic win row is Tagged Count goblin equals 0 — every goblin gone; **Read Tagged Count** copies that count into a variable, so a label can show how many are left or Save Game can keep it. Matching ignores capitals, so Goblin and goblin are the same tag, and an object holds at most 16. Runtime tags last until the scene loads again — the Inspector chips are the permanent ones, restored on every scene load. Old projects behave exactly as before: an object with no tags simply has none, and tags already on objects (used by the Hierarchy search) now work in blocks too.
- Boss encounters: a run now has a climax. **Start Boss** names the boss object and picks how many phases the fight has — 2 to 5, 3 by default — and a wide health bar with the boss's name appears across the top of the screen. The phases are equal slices of the boss's health bar, so with 3 phases the fight is in phase 1 down to two thirds of its health, phase 2 down to one third, and phase 3 to the end. **Boss Phase** is the condition that reads the phase number, so the behavior per phase is ordinary blocks: Boss Phase at least 2, then Set AI Behavior to chase faster, Set Scaling Rates harder, Start Spawner for minions. **Boss Active** is true from Start Boss until **End Boss**, even before the boss spawns, so the fight music and the arena doors can gate on it. **Read Boss Phase** copies the phase number into a variable, and **Show Boss Bar** / **Hide Boss Bar** toggle the bar without ending the fight, so a cutscene can clear the screen and bring it back. Nothing ends the fight on its own: chain End Boss after Object Died on the boss, on the same row as the win screen or the XP reward. One boss at a time — starting a second boss replaces the first — and the fight survives scene switches inside a run, resetting only when the game starts over. A boss that has not spawned yet reads phase 0 and shows no bar until a live object with its name exists. Old projects behave exactly as before.
- The Apply Force block's arrow now points in the force's direction. A placed block draws its arrow rotated by the force it carries — right for +X, left for -X, down for +Y, up for -Y, diagonally for a mix (so (-100, 0) points left and (100, 100) points down-right) — and editing X or Y in the panel re-points the arrow as you type, with the direction saved and restored on reload. When X or Y holds an expression instead of a number, the arrow stays pointing right, since an expression has no static direction; the palette icon stays generic too. Old projects behave exactly as before.
- Fixed: Apply Force, Set Velocity, and Knockback Object used to do nothing on an object without physics turned on — the force wrote a velocity the engine never moved. Velocity is now universal: any object except text and static ones moves on its velocity, gliding at a steady speed, while gravity, friction, and collisions still only apply to physics objects. A plain object pushed by a force glides straight through floors and trigger zones instead of landing on them, and the block notes and guides now say so. Old projects behave exactly as before, except a force on a plain object now does what it always looked like it should.
- Fixed: the device-frame preview stretched the game to the device's shape. A portrait phone frame showed the 800x600 game at the phone's tall aspect, so circles became tall ellipses. The preview now letterboxes the game inside the frame at one uniform scale — the game keeps its own aspect ratio, the way a real phone letterboxes instead of stretching — so a landscape game on a portrait phone shows as a wide strip with empty bezel above and below it, and the same for landscape phones and tablets. The game itself still renders at the scene's viewport size; only how big it is shown changes. Old projects behave exactly as before.
- Fixed: dragging from a locked object used to deselect it. The lock correctly stopped the drag, but the press-on-object / release-elsewhere click was read as a click on empty scene, so the editor cleared the selection and emptied the Inspector. A press that starts on an object no longer counts as a click on empty scene, so the locked object stays selected and inspectable; clicking genuinely empty scene still deselects.
- Fixed: double-clicking an object's name in the Hierarchy list never opened the rename box. The first click of the double-click rebuilt the list (replacing the name under the pointer) and switched to the Inspector tab (hiding the list), so the second click could never land. Clicking a row's name now selects the object in place and stays in the list, so the double-click lands and the rename box opens; clicking anywhere else on the row still opens the Inspector as before.
- The build-the-editor test is done (P5-9, completing the whole core-engine track): there is a new **Variable Inspector** starter template. It is a working variable panel built only from HydraScript blocks — it lists the score, coins, goblin HP, and a name, lets you change them with - / + buttons or by typing a number and pressing Set, and watches them change while you play (grab the coin, bump the goblin, beat the goblin for +50). No block sets the starting values; they come from the game's own variable definitions, so the panel shows what the game actually holds. One new Variables block makes the typed row possible: **Read Text Into Variable** reads what a text object shows back into a variable — as text, or parsed as a number — so a number a player types can drive the game. A bad keystroke never clobbers the variable: text that is not a number warns and the old value stays. Old projects behave exactly as before.
- Fixed: the editor could fail to finish loading, leaving the Create panel hidden and the inspector tabs dead. A variable the outliner needs was declared after the setup call that reads it, so the setup threw and the rest of the editor never ran. The declaration now comes first, and a new test pins the ordering so it cannot slip back.
- Fixed: in the smoke-test flow, opening the flagship template could silently switch the main editor to the flagship project (both pages shared one browser's saved current-project setting, and the next reload on the main page opened the flagship instead of the collector). The template pages now run in their own browser contexts, so creating a project on one page can never steer another page's reload.
- Compact-density option for blocks (P5-8 slice c, completing the pro editor shell pass 2): the Logic tab has a **Compact blocks** button next to the Dock button. Click it and the logic-grid cells shrink from 56px to 44px, with the block labels shrinking with them, so about a quarter more columns fit across the same stage — handy when a chain runs long or a fan-out runs wide. Click it again for the comfortable 56px cells. It changes nothing about the game: the grid is still 60 columns wide, the blocks and chains mean exactly the same thing in either density, and saved projects open the same way. The choice sticks: it is saved in your browser and restored the next time you open the editor. The puzzle-piece block shapes scale with their cell, so a compact block keeps its silhouette. Old projects behave exactly as before.
- The Hierarchy tab is now an outliner (P5-8 slice b, the second piece of the pro editor shell pass 2): objects group under collapsible headers by layer, highest layer first, so a busy scene reads at a glance instead of as one long list — collapsing a layer tucks its objects away, and which layers are collapsed is remembered in your browser. Each row has an eye and a lock. The eye sets starting visibility: a hidden object is gone from the editor stage and the 3D view, and it also starts the game hidden, until a Show Object block brings it back — it is a starting state, not just an editor filter, and the row stays listed and dimmed so the object is never lost. The lock is editor-only: a locked object can still be selected and inspected, but it cannot be dragged or painted over on the canvas. Double-click a name to rename it in place, and arrow keys walk the rows (Enter opens the Inspector). The Inspector now opens with a one-line summary — what the object is, its layer, its id — plus Visible and Locked checkboxes that do the same thing as the row buttons. Old projects behave exactly as before.
- Dockable editor panels (P5-8 slice a, the first piece of the pro editor shell pass 2): the Scene inspector and the Logic panel can each dock to the left edge of their tab instead of the right. A Dock button at the end of the scene toolbar flips the inspector, and one next to the block search flips the Logic panel; click it again to dock back on the right. The stage, the toolbar, and the resize handle move with the panel, so the layout reads the same way, mirrored, and a left-docked panel keeps its width and still drags wider and narrower from its right edge. The side sticks: it is saved in your browser and restored the next time you open the editor. On narrow screens the panels dock below their main area instead, so the side choice has no visible effect there. Old projects behave exactly as before.
- Core unification remainder (P5-7): one flow module, and the row-60 bug is fixed. There used to be four separate copies of the code that decides which blocks sit next to each other on the logic grid — the shared flow module, the export player, the editor preview, and the diagnostics view — and they had drifted apart: the shared module and the export capped grids at 60 rows, so on a grid taller than 60 rows (Neon Arena's arena grid runs about 244 rows) every link downward past row 60 silently vanished, and an `and` sitting past that line saw zero neighbours and never passed. Now `hydra-flow.js` is the one definition of flow adjacency, with no row cap (the grid is 60 columns wide, rows are unbounded), the export player and the editor preview both resolve through it, and the diagnostics view mirrors it, so a fix lands everywhere at once. The preview and the export also now agree on fan-out order — right, down, left, up — where the preview's old copy ran neighbours up, down, left, right. A new golden test runs one project through both runtimes and proves the outputs match exactly, including a chain past row 60. Old projects behave exactly as before, except tall grids that were silently broken past row 60 now run the way their layout says they should.
- Iteration over structures (P5-6 slice c, completing data structures): one new Control Flow block. **For Each Field** runs the blocks to its right once per field of a structure — the dictionary the structure blocks build — handing the body the field name as text and the field's value each round, with an optional index variable counting 1, 2, 3, so a stats sheet sums one field at a time and a squad stored as a structure walks one member at a time. When a field holds an object handle, the body round also points the rest of the chain at that live object, so Damage Object in the body hits that one member and not the others. The fields are snapshotted at the start, so a body that adds or removes a field does not change the run; a structure with more than 1000 fields runs only the first 1000 and warns, and a variable that holds no structure warns and nothing runs. The keys-list path walks the names only — List Structure Keys into a list, then For Each Item over the keys — because Get Structure Field takes a fixed field name. Old projects without this block behave exactly as before.
- Object references inside structures (P5-6 slice b): two new Variables blocks. **Store Object In Structure** writes the object a scoped variable holds into a list or dictionary at a path — `squad[0]` stores the clone in the first slot of the squad list, `party.leader` stores it in the leader field — building the lists and structures it needs on the way down, like Set Nested Value, so a squad list of live objects grows one store at a time. **Read Object From Structure** reads the object at a path back into a scoped variable, so the game can walk a party list one member at a time and read each member's position, health, or alive flag with Read Object Property, and chained actions after the read hit that one object. A missing step, or a value that is not an object, clears the variable, so a later Is alive read is 0 and the variable never holds a stale member. A blank variable name, blank path, blank object variable, or object scope with no object warns and holds, and an index past the 10,000 cap warns and changes nothing. The manual way still works and means the same thing: Read Scoped Variable copies the handle into an ordinary variable, Set Nested Value stores that copy at the path, and Get Nested Value plus Read Object Property reads it back. Old projects without these blocks behave exactly as before. Iteration over structures has since landed with For Each Field (see above).
- Nested paths (P5-6 slice a, the first data-structures primitive): two new Variables blocks. **Get Nested Value** reads a value deep inside a list or structure in one block — `party[0].hp` reads the hp field of the first dictionary in the party list, `player.stats.hp` reads a field of a field — into another variable, so an expression or a label can use it; a missing step reads as 0. **Set Nested Value** writes `party[0].hp = 10` and builds the lists and structures it needs on the way down (a list step grows the list with 0s, a field step creates the dictionary), so a party list of member dictionaries grows one path write at a time. A blank or malformed path warns and holds, and an index past the 10,000 cap warns and changes nothing. The manual way still works and means the same thing: Get Array Item into a temp variable, Set Structure Field on it, Set Array Item back. Old projects without these blocks behave exactly as before. Iteration over structures has since landed with For Each Field (see above).
- Melee Attack and Shoot Projectile are presets now, with the full rebuild in the user guide (P5-5 slice d, completing object primitives). Both come apart into ordinary blocks you can build by hand and change: the melee swing is List Overlapping Objects around the hero, For Each Item, and a Damage Object whose amount is `swingAng <= 0.785 ? 10 : 0` so only goblins inside the 90-degree arc take the hit; the shot is Spawn Object Into Variable handing the clone back, Pick Nearest re-acquiring it every frame, Move Toward Position flying it, an overlap circle riding on it for the hit, and a timer for its lifetime — one hit, then the shot is destroyed. The one-block versions stay and keep working exactly as before. Two things the rebuilds do not carry over, stated in the guide: Attack Ready reads the combat module's cooldowns, which the rebuilds never touch (they pace themselves with timers), and growth and scaling damage bonuses do not ride along (read them and add them in the amount). One shot at a time for now — firing again while a shot flies strands the first one.
- The browser tests no longer fail the suite when Chromium itself cannot launch: the playtest release gate and the browser smoke test now check with a real headless launch first and skip loudly instead of crashing, since a Chromium install can exist yet die on launch. The manual harness run before shipping is still required.
- Spawn and destroy as instantiation (P5-5 slice c): two new Variables blocks. **Spawn Object Into Variable** spawns a copy of an object and hands the clone back in a variable you name, so the game can keep track of one spawned enemy, one bullet, one coin and act on only that one — actions chained after the spawn that target the object's name hit only the clone, and a Read Object Property after it reads the clone's position, health, or whether it is still alive. **Destroy Object In Variable** destroys exactly the object a variable holds — the clone a spawn handed back, or the goblin a pick chose — not every object with that name, so a spawned enemy can be removed without touching the original. A spawn of a missing source clears the variable instead of leaving a stale clone in it, and a blank object or variable name warns and holds. Old projects without these blocks behave exactly as before.
- Physics queries that return data (P5-5 slice b): two new Variables blocks. **Raycast Into Variables** casts a ray and puts what it finds into variables — the hit object into a variable you name, and the distance into another — so a laser, a line of sight, or a "what is in front of me" check can act on exactly the object it hit; a miss writes distance -1 and clears the object variable. **List Overlapping Objects** finds every object inside a circle and puts the list and its count into variables, so one loop can damage, collect, or count everything nearby. A loop over that list can read each object's position, because Read Object Property now also reads a handle held in an ordinary variable, and For Each Item hands each object to its body the same way For Each Object does.
- Object references as values (P5-5 slice a): a variable can now hold an object, not just a number or text. **Pick Object Into Variable** picks one live object — nearest, farthest, random, or first — and stores it in a scoped variable, so the game can keep track of one goblin, one coin, one bullet; actions chained after the pick that target the object's name hit only the picked object. **Read Object Property** reads one property of the held object back into an ordinary variable: position, size, rotation, velocity, health, max health, its name, or whether it is still alive (1 or 0). A reference keeps the object's name and id, so a destroyed object reads as gone (0, or empty text for Name) instead of silently retargeting a different object with the same name, and the Live variables panel shows a held object by its name.
- Object dropdowns now say what they mean when nothing is picked. An unset object field used to display the first object's name while storing nothing, so a fresh block looked like it was already set to the player; it now shows (none), or (No named objects yet) when the scene has no objects. The same fix stops a fresh scoped-variable block from silently binding its scope object to the first object: with Global, Scene, or Local scope the scope object stays blank, and switching the scope to Object without naming one warns instead of quietly picking the first object.
- Functions manager polish (P5-3 slice c, completing functions / custom blocks): every function row now has a **Duplicate** button that copies the function under a new name like add copy, with the same parameters and a copy of the body, so a variant starts from a working chain instead of an empty grid. Each row also says how many times the function is called, or that it is not called yet, so a dead helper and a workhorse read differently at a glance. And if you type a duplicate parameter, or more than eight, the panel keeps the first eight unique names and tells you which ones it dropped instead of trimming the list silently.
- Functions, better arguments and validation (P5-3 slice b): a function now takes up to eight parameters instead of four, and the **Call Function** panel shows one argument field per parameter, labeled with the parameter name — calling sum8 shows fields a through h instead of four generic Argument 1–4 slots, and picking a different function rebuilds the panel to match. The Functions manager rows wrap cleanly now, so a long parameter list can no longer squeeze the function's name away, and the badge shows the full list on hover. Block validation covers function bodies like any other grid: the diagnostics panel flags a Call Function that names a function that does not exist, a Return From Function placed outside a function body, and a bad expression inside a body.
- Resizable editor panels (P5-2 slice d, completing the pro editor shell pass 1): the Scene inspector and the Logic panel both have a drag handle on their left edge — drag it to trade stage space for panel space, wider when a property form needs room, narrower when the scene needs it. The widths stick: they are saved in your browser and restored the next time you open the editor. Double-click a handle (or focus it and press Home) to snap back to the default width, and the arrow keys resize a focused handle without a mouse (Shift steps further). On narrow screens the panels dock below their main area instead, so the handles hide there.
- Muted editor palette (P5-2 slice c, pro editor shell pass 1): the editor's buttons, tabs, and highlights use softened, less saturated colors — Save, Export, Add Block, the inspector tabs, focus rings, and the export dialog's amber are all a step quieter, so the workspace stays calm and the blocks on the logic grid stand out. The block colors themselves are unchanged (blue is still a condition, red is still an action), the HydraScript logo keeps its violet-blue gradient, and white text on buttons stays as readable as before. Pass 1 is now complete with resizable panels in slice d.
- Denser editor panels and a smaller type scale (P5-2 slice b, pro editor shell pass 1): the inspector and logic panels use a dense 12px type scale with tighter spacing, so more controls fit on screen at once — buttons, tabs, and panel text are a step smaller, panel sections and property rows are 2px tighter, and the block palette rows are shorter. The header and tab heights, the 56px logic grid, and the status bar are unchanged, and the colors moved separately as the muted palette in slice c, so the editor looks familiar, just denser.
- Redirect: the P5 core-engine track is now the highest priority, and the P4 Advanced batches are PAUSED (Ky'lin's direction, Nov 6, 2026, evening). Real engines ship primitives — variables, functions, objects, physics queries, events — not one-block "attack" / "shoot" / "level" / "elite" systems, and a one-block Melee Attack / Shoot Projectile limits what a user can build because the mechanism is hidden inside the block. From here on: no new canned game-action blocks, primitives first, and any preset ships with its visible decomposition (its own block chain, documented, rebuildable by hand). The P5 track, in order: Variables v2 with real scopes (the foundation — today variables are one flat global dict), pro editor shell pass 1, functions / custom blocks, control flow + events, object primitives plus decomposing attack/shoot back into primitives, data structures, the core unification remainder (one flow module, porting the row-60 fix), pro editor shell pass 2, and the build-the-editor acceptance test (a working variable inspector built only from HydraScript blocks inside a game). Existing canned blocks (Melee Attack, Shoot Projectile, leveling, scaling) keep working for backward compatibility — they are presets now, not the model for new work. Batch 33 (elite / boss enemy presets) was cancelled mid-cycle and its work reverted uncommitted, so no elite blocks ship.

### Added
- Custom events (P5-4 slice c, completing control flow + events): two blocks in the **Control Flow** category — **Broadcast Event** (send a named event from any chain) and **On Event** (a condition that is true for one frame when that name is broadcast, so the blocks to its right run once per broadcast). A coin that scores, a boss that dies, a door that opens: the block that knows says so by name, and every chain that cares listens for that name, instead of polling a variable or reaching across the grid. A listener after the broadcaster in the grid fires in the same frame; a listener before it fires on the next frame — either way exactly once per broadcast, and a broadcast every frame fires the listener every frame. An event carries no value with it, so set a variable first when the listener needs a number or a name. The event state survives scene switches inside a run. Old projects without event blocks behave exactly as before. Honest limits: an event name is plain text, not an expression, so it cannot be built from a variable at run time; a listener for a name that is never broadcast stays quiet with no warning, so spell the name exactly the same on both blocks; no hs script-API surface yet (use the blocks). P5-4 is now complete; next is P5-5 object primitives.
- For-each loops (P5-4 slice b, the second control-flow primitive): two blocks in the **Control Flow** category — **For Each Item** (run the blocks to its right once for every item in a list — build the list first with Push To Array and friends, then the item variable holds the item each time round and the index variable, when named, counts 1, 2, 3, so adding every score in a list is one loop instead of one row per item) and **For Each Object** (run the same rightward body once for every live object with one name — body actions that target the object hit one object at a time, the current one, so the same chain can heal every goblin or move every coin; the index variable counts the objects the same way). A list with more than 1000 items runs only the first 1000 and warns, and a variable that holds no list warns and nothing runs; no live objects runs nothing. Old projects without for-each blocks behave exactly as before. Honest limits: the body cannot read the current object's position into a variable yet, and a dict is not a list, so For Each Item over a dict warns and holds. Custom events (broadcast / listen) landed as slice c, completing P5-4.
- Loops (P5-4 slice a, the first control-flow primitive): four blocks in a new **Control Flow** category — **Repeat** (run the blocks to its right on the same row a set number of times, with an optional counter variable that counts 1, 2, 3 up to the count so the body can use it), **While** (run the same rightward body while a comparison holds — pick two values and one of six comparisons), **Break** (stop the innermost loop at once and carry on after it), and **Continue** (skip the rest of this round and start the next one). The body is the blocks to the loop's right on the same row; a condition, an empty cell, or the row end stops it. A loop that runs past 1000 times stops at 1000 with a warning, loops nest up to 8 deep, and a frame's loop work caps at 10,000 body actions, so a runaway loop warns and stops instead of freezing the game. Break and Continue outside a loop warn and do nothing. Old projects without loops behave exactly as before. Honest limits: the body must sit to the loop's right on the same row (blocks below it are not the body); a test that never changes stops after 1000 rounds with a warning, so change a variable inside the body and test that variable; no hs script-API surface yet (use the blocks). For-each loops landed as slice b and custom events as slice c, completing P5-4.
- Functions / custom blocks (P5-3 slice a, the functions runtime core — the composability primitive): write a chain of blocks once and call it from anywhere. The **Functions** tab in the Scene inspector lists the game's functions — add one with a name and up to eight parameters (comma-separated, behind an "Add a function" disclosure), then click **Edit body** to open its own grid, a scope tab marked with ƒ, and build the chain there like any other grid. Two blocks in the new **Functions** category — **Call Function** (pick the function, fill in up to eight arguments as expressions, store the return value in an ordinary variable or leave it blank to throw it away) and **Return From Function** (hand a value back to the caller and stop the rest of the body; a function with no Return returns 0). The parameters arrive inside the body as **local** variables — a fourth scope only that call can see — so the same function adds 3 + 4 one moment and 10 + 20 the next, and each call gets its own fresh locals: a local set inside the body never leaks out, and a second call starts from clean parameters. A body never runs on its own, only when Call Function names it, and a gameStart block inside a body fires only on the first call of the run. Calls nest, and a function can call itself, but the stack caps at 32 deep — the 33rd call is skipped with a warning and returns 0. Rename a function and every Call Function block naming it follows; deleting one asks first when calls still name it, and a missing function warns and holds instead of crashing the game. Old projects without functions behave exactly as before. Honest limits: arguments are expressions, so parameters always arrive as numbers — set text locals inside the body with Set Scoped Variable if the body needs text; eight parameters at most, and the Call Function panel shows one argument field per parameter, labeled with the parameter name; function bodies are covered by block validation (see the slice-b note above); no hs script-API surface yet (use the blocks). Still to come in P5-3: manager/body-editing polish.
- Status bar (P5-2 slice a, the first piece of the pro editor shell): a thin bar along the very bottom of the editor that always shows the current scene name, how many objects the current scene has, the live preview FPS, and how many diagnostics are open. FPS reads a dash while no preview is running and a live number while the Preview tab plays; the diagnostics count turns amber when something is open, and clicking it opens the diagnostics panel. Pass 1 is now complete: denser panels and a smaller type scale landed as slice b, the muted palette as slice c, and resizable panels as slice d.- Variables manager panel + Scoped Variables Demo (P5-1 slice b, completing P5-1 — variables with real scopes for beginners): the Variables tab in the Scene inspector now lists every variable the game starts with, grouped by scope — Global (whole game), Scene (each visit starts from the starting value), Object (one value per object name) — with its starting value. Add one there (name, scope, object when it is an object variable, type, starting value, behind an "Add a variable" disclosure) and the game begins with it: no block has to set it first. Global definitions seed when the game starts, object definitions seed with them, and scene definitions seed every time their scene loads. - Physics joints, batch 4 (Advanced): link two objects so they move together — a lantern swinging from a ceiling, a trailer towed behind a truck, a bungee cord, a wrecking ball on a chain. A joint lives on the scene and links two objects by name, and the solver runs every frame in the editor preview and in exported games (after collisions, so joints and walls agree). Three kinds: **Distance** is a rigid rod (the two centers stay exactly the length apart; length 0 welds the centers together), **Rope** is a chain (the centers may come closer freely but never stretch past the length — a hanging lantern is a rope from a static ceiling anchor to the lantern), and **Spring** is a stretchy cord (it pulls both ends toward the rest length, damped so it settles instead of bouncing forever; Stiffness 0 to 1, default 0.05, sets how hard it pulls). The no-blocks way in is the Inspector's new **Joints** section on any 2D physics object: pick the other object, the type, a length (leave it blank to use the distance they are apart right now), and a stiffness for springs, then **+ Add joint**. Static objects act as anchors that never move. Three new **Physics** blocks do it at runtime: **Create Joint** (links two objects; leave Length blank for their current distance; re-creating the same pair and type replaces the old joint, so a rod and a spring on the same pair can coexist; bad type, length, stiffness, or a missing endpoint warns and holds, blank names stay quiet), **Remove Joint** (unlinks two objects; leave Object B blank to remove every joint involving Object A), and the invertible **Joint Connected** (true while a joint links two objects, either direction; leave Object B blank to test whether Object A has any joint — a state read that evaluates every frame and while paused). Honest limits: joints connect object centers, with no anchor offsets and no rotation or angular physics, so a "hinge" here holds centers together rather than swinging a body around a pivot; joints ignore collision layers (a joint holds even across layers); joints are 2D only (3D objects never solve); a joint whose endpoint is missing, hidden, or destroyed simply does nothing that frame instead of breaking the game. Identical in the editor preview and in exported games (the new `hydra-joints.js` module is inlined into exports); corrupt data normalizes instead of crashing.

- Sprite animations (GDevelop-style): each object can have an animation list — name, Loop / Ping-pong / Play-once mode, frames per second, and an ordered frame strip built from image assets in the Assets tab, with a live preview in the Inspector and an optional play-at-start animation. Four new logic blocks drive them: Play Animation, Set Animation (switch without restarting), Stop Animation, and Animation Finished (fires when a play-once animation completes). Everything works identically in the editor preview and in exported games; corrupt animation data normalizes instead of crashing.
